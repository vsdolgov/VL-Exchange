# VL Exchange

**Экспериментальное предложение VL · русский | [English](README.md)**

[GitHub: vsdolgov/VL-Exchange](https://github.com/vsdolgov/VL-Exchange)

Видеоаналитику должно быть проще переносить между платформами.

Разработчик должен иметь возможность продавать своё решение на любой совместимой платформе, заказчик — выбирать платформу без потери уже оплаченной аналитики, а интегратор — переносить работающие решения, а не разрабатывать их заново.

## Зачем это нужно

Одного файла модели для переноса работающего решения недостаточно. Новой платформе также нужно знать, как подготовить изображение, обработать результат модели и определить, когда создавать событие. Например, разные платформы могут по-разному понимать условие «человек в зоне».

VL Exchange предлагает общие форматы пакетов, в которых можно передать эти сведения. Они дополняют существующие технологии: ONNX описывает вычисления модели, RTSP передаёт видеопоток, а ONVIF определяет интерфейсы совместимости. Пакеты добавляют информацию, необходимую платформе для работы решения.

ИИ помогает разобраться в другой платформе и написать адаптер. Общие форматы могут дополнительно сократить повторную работу при интеграции и сохранить конкуренцию между платформами. При этом участникам всё равно нужно согласовать смысл событий, условия лицензии и испытания; конкретный процент экономии мы не обещаем.

## Как это работает

- **VLMP (VL Model Package)** объединяет модель, зависимости, обработку данных, описание результатов и проверочные примеры.
- **VLSP (VL Scenario Package)** описывает исполняемую логику сценария: входные данные, параметры, состояние и события.
- Платформа поддерживает пакет через собственный адаптер. Исполнитель или облако VL для этого не обязательны.

VLBP — отдельный внутренний формат блоков VL. Он не нужен для работы с публичным интерфейсом; также не требуется определённый визуальный редактор или архитектура блоков.

Спецификация интерфейсов открыта. При этом модели и прикладной код могут оставаться коммерческими, поставляться в зашифрованном виде и лицензироваться для работы онлайн или офлайн. Совместимость сама по себе не переносит лицензию: возможность сменить платформу без повторной покупки должна быть предусмотрена правообладателем. В текущем прототипе защищённой выдачи поставка привязана к установке, поэтому для переноса нужен разрешённый перевыпуск лицензии и ключей. Копирование секрета не переносит право использования.

## Текущее состояние

Это экспериментальное предложение для обсуждения, **а не утверждённый отраслевой стандарт**. Совместимость с платформами других производителей пока не проверена. В примерах используются синтетические данные; они не показывают качество промышленных детекторов.

| Компонент | Версия и профиль | Что проверено |
|---|---|---|
| Исходный пилот VLMP | 0.1.0, CustomModelProtocol / CPU ONNX FP32 | Ранее проведён локальный пилот с реальным загрузчиком Box 5. Его закрытого SDK в репозитории нет. |
| Публичный VLMP | **0.2.0-draft.1**, python-numpy-classification-v1 | Самостоятельный пример без закрытых SDK: два локальных загрузчика используют одну ONNX Runtime. Этот профиль не проверен с Box 5. |
| VLSP | 0.1.0, python-scenario-json-v1 | Два независимо реализованных исполнителя запускают пример классификации и формируют события и состояние в JSON, без VLBP. |
| Защищённая выдача | 0.1.0 | Прототип шифрования, подписи и прав на работу онлайн и офлайн с локальным тестовым сервисом. Это не песочница и не промышленный сервер лицензий. |

Публичный профиль VLMP — новое предложение, отдельное от пилота 0.1. Результат пилота с Box 5 на него не переносится. Поддержка произвольных моделей, GPU, треков и всех видов видеоаналитики не заявлена. Результаты и команды — в [матрице совместимости](docs/ru/COMPATIBILITY.md).

## Начать за несколько минут

Требуется CPython 3.12 и публичные зависимости. Из корня репозитория:

```sh
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
export PYTHONDONTWRITEBYTECODE=1
export PYTHONPATH="model/src:scenario/src:security-runtime/src"
python model/src/public_model.py validate model/examples/channel-classifier
python model/src/public_model.py golden model/examples/channel-classifier
python model/tools/independent_host.py model/examples/channel-classifier
python tools/model_archive_roundtrip.py
python -m vl_scenario_package golden scenario/examples/target-scenario --policy development
python scenario/tools/independent_host.py scenario/reports/vlsp-target-scenario.zip
python -m pytest -q
python tools/check_links.py
```

Online-тесты открывают HTTP только на loopback; окружение должно разрешать локальные сокеты. В CLI `--policy development` нужен явно для открытого примера; эксплуатационный путь по умолчанию требует защищённую поставку. В публичных примерах нет постоянных ключей: тесты создают временные ключи и удаляют расшифрованные данные.
