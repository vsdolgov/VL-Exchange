# VL Exchange

**Экспериментальное предложение VL · русский | [English](README.md)**

VL Exchange — проект **открытого стандарта обмена моделями и сценариями видеоаналитики** между совместимыми платформами. В репозитории собраны проекты спецификаций, примеры реализаций и тесты.

Наша цель: разработчик может продавать решение на любой совместимой платформе, заказчик — выбирать платформу без потери уже оплаченной аналитики, а интегратор — переносить работающие решения, не разрабатывая их заново. Возможность переноса также зависит от лицензии правообладателя решения.

Спецификации обмена предполагаются открытыми, без коммерческой лицензии. Конкретные юридические лицензии на спецификации, схемы и код проекта ещё не утверждены; сама публикация пока не предоставляет предложенных лицензионных прав. Предполагается, что платформы смогут реализовывать эти интерфейсы в коммерческих продуктах, а модели и сценарии — распространяться на собственных условиях. Подробнее — в [предложении по лицензиям](docs/governance/LICENSE-PROPOSAL.ru.md).

## Зачем это нужно

Файл модели — лишь часть работающего решения. Принимающей платформе также нужно знать, как подготовить данные, понять результат и когда создать событие. Например, условие «человек в зоне» разные платформы могут трактовать по-разному. Это пример возможной задачи, а не готовый детектор в репозитории.

ИИ помогает разработчикам разобраться в другой платформе и написать адаптеры. Общие правила обмена могут сократить повторную работу при интеграции, сохраняя конкуренцию между платформами. Участникам всё равно нужно согласовать смысл событий, лицензии и проверки.

## Как это работает

1. Разработчик готовит пакет с моделью или сценарием и описанием их работы.
2. Платформа принимает пакет через свой адаптер — компонент, связывающий пакет с платформой.
3. Модель выдаёт результат, а сценарий использует его и контекст для создания событий.

**VLMP (VL Model Package)** объединяет модель, зависимости, обработку данных, описание результатов и проверочные примеры. **VLSP (VL Scenario Package)** содержит исполняемую логику сценария, его входы, параметры, состояние и события. Адаптер можно реализовать самостоятельно; исполнитель, облако и визуальный редактор VL не обязательны. Внутренний формат блоков VLBP не входит в публичный интерфейс обмена.

VL Exchange дополняет ONNX, RTSP и ONVIF: эти технологии решают задачи вычисления модели, передачи видео и взаимодействия с устройствами, а предлагаемые пакеты добавляют прикладную информацию для запуска решения.

## Авторство и бренд

Необязательный экспериментальный профиль позволяет указать издателя, авторов модели или сценария, предпочтительную подпись и правила её отображения. Поддерживающая платформа может сохранить эти сведения в аналитических данных и показать подпись, например `Analytics by Detector Lab`, в видеопотоке или производной видеозаписи. Авторы модели и сценария и производитель платформы указываются отдельно. Профиль работает без подключения к сети; старый исполнитель может его проигнорировать. Поддержка сторонними платформами пока не подтверждена. Подробнее — в [профиле Attribution & Branding](docs/ru/ATTRIBUTION.md).

## Реальный пример в репозитории

Публичная демонстрация использует **синтетическую классификацию цветов**, а не детектор человека. Пример модели выдаёт метки `red`, `green` и `blue`. В примере сценария два последовательных результата `red` от одного источника в одном запуске, каждый с оценкой не ниже 0,5, приводят к событию JSON типа `org.vlexchange.target-observed.v1` с полями `label`, `score` и `count` в полезной нагрузке. См. [пример модели](model/examples/channel-classifier) и [тестовую последовательность сценария](scenario/examples/target-scenario/golden/basic.json).

По такому принципу в будущем можно описать и другие задачи, например человека в зоне, когда будут подготовлены подходящие модели, профили и проверки. Учебный пример не подтверждает качество детекторов или совместимость с платформой другого производителя.

## Что доступно сегодня

- Проекты спецификаций VLMP и VLSP и синтетические примеры можно изучить и проверить локально.
- Локальные проверки используют два независимо реализованных исполнителя. В публичном примере VLMP оба используют один ONNX Runtime; исторический пилот Box 5 работал с другим профилем VLMP.
- Прототип защищённой поставки проверяет подпись, шифрование и права запуска онлайн и офлайн с локальным тестовым сервисом. Это не песочница и не промышленный сервер лицензий.

Это предложение **ещё не утверждённый отраслевой стандарт**. Совместимость с платформами других производителей пока не проверена. Публичный профиль VLMP `0.2.0-draft.1` не проверен с Box 5 и не наследует результат прежнего пилота 0.1. Поддержка произвольных моделей, GPU, треков и всех видов видеоаналитики не заявлена. Профили, результаты и ограничения — в [матрице совместимости](docs/ru/COMPATIBILITY.md).

## Попробовать примеры

Команды ниже рассчитаны на macOS или Linux; нужны Git, CPython 3.12 и интернет для установки публичных зависимостей. В терминале:

```sh
git clone https://github.com/vsdolgov/VL-Exchange.git
cd VL-Exchange
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
export PYTHONDONTWRITEBYTECODE=1
python model/src/public_model.py golden model/examples/channel-classifier
PYTHONPATH=scenario/src python -m vl_scenario_package golden scenario/examples/target-scenario --policy development
```

При успехе обе проверки выводят JSON-отчёт с `"status": "pass"`. Первая сверяет результаты модели с ожидаемыми значениями. Вторая проверяет события и состояние сценария на заранее подготовленных результатах классификации из JSON; модель она не запускает. Описанная выше цепочка от модели к событию показывает замысел интеграции; отдельный [отчёт сквозной проверки](reports/pipeline.json) фиксирует локальный тест с фактическим результатом модели. Это синтетические локальные примеры, а не испытание внешней платформы. Параметр `--policy development` разрешает работу открытого учебного примера; эксплуатационный путь CLI по умолчанию требует защищённой поставки. Полные проверки, настройка окружения и работа с адаптером описаны в [руководстве](docs/ru/GUIDE.md) и [матрице совместимости](docs/ru/COMPATIBILITY.md).

Для участия не нужно раскрывать коммерческие веса модели или код сценария. Для обсуждения достаточно синтетического примера, адаптера и воспроизводимого отчёта с ограничениями.

Спецификации обмена предполагается сохранить открытыми, без коммерческой лицензии. Конкретные лицензии на спецификации, схемы и код проекта, а также патентная политика пока не утверждены. В текущем прототипе защищённой поставки для переноса установки нужен разрешённый перевыпуск лицензии и ключей; копирование секрета не переносит права. Не добавляйте ключи, записи заказчиков, закрытые SDK или веса моделей без разрешения. См. [правила участия](CONTRIBUTING.ru.md) и [список изменений](CHANGELOG.ru.md).
