# VL Exchange

**Draft / Experimental · инициатива VL · русский | [English](README.md)**

[GitHub: vsdolgov/VL-Exchange](https://github.com/vsdolgov/VL-Exchange)

Разработчик должен иметь возможность продавать своё решение на любой совместимой платформе, заказчик — выбирать платформу без потери уже оплаченной аналитики, а интегратор — переносить работающие решения, а не разрабатывать их заново.

Сегодня смена платформы часто означает повторную разработку уже работающей видеоаналитики. Файл нейросети можно экспортировать, но вместе с ним не переезжают порядок цветовых каналов, нормализация, классы, пороги, координаты, состояние сценария и правила появления событий. Одно и то же слово «человек в зоне» может обозначать разные условия, интервалы времени и правила подавления повторов.

Инженерная цепочка выглядит так: **модель → входные данные → предобработка → inference → постобработка → контекст → сценарий → событие**. ONNX описывает вычисления модели, RTSP помогает передать медиапоток, ONVIF задаёт свои интерфейсы совместимости; принимающей системе всё равно нужен однозначный интерфейс прикладного решения. VL Exchange предлагает согласовать такой интерфейс поверх существующих технологий.

ИИ-помощники могут упростить написание адаптеров, разбор чужого API и перенос прикладной логики. Наша позиция: общий интерфейс позволяет направить эту помощь на проверяемый результат и экономить ресурсы на повторной интеграции, сохраняя конкуренцию платформ и разработчиков. ИИ не заменяет согласование смысла события, условий лицензии и испытание одного неизменённого пакета в независимых системах; обещаний конкретного процента экономии здесь нет.

## Что мы предлагаем

**VLMP — VL Model Package** связывает модель, зависимости, исполняемую обработку данных, семантику результата и контрольные примеры. **VLSP — VL Scenario Package** переносит исполняемую логику сценария с форматами входа, параметров, состояния и событий. Принимающий производитель реализует совместимый адаптер на своей платформе. VL не является обязательным поставщиком исполнителя или облачной службы.

VLBP — отдельный внутренний формат блоков VL. Он не является частью публичного межвендорного интерфейса; редактор и архитектура блоков не требуются.

Открыта спецификация интерфейсов. Модель и прикладной код могут оставаться коммерческими и поставляться зашифрованными, с offline либо online правом исполнения. Техническая совместимость не переносит автоматически лицензию: возможность сменить платформу без повторной покупки аналитики должна быть предусмотрена договором правообладателя. Текущий прототип защищённой выдачи привязывает поставку к установке; при переносе требуется разрешённый перевыпуск лицензии и ключей. Копирование старого секрета не является переносом права.

## Статус и границы

Это предложение VL для обсуждения с рынком, не утверждённый отраслевой стандарт. Совместимость с платформами сторонних производителей пока не проверена. Демонстрации синтетические и не показывают качество промышленных детекторов.

| Часть | Версия и профиль | Состояние |
|---|---|---|
| VLMP исходного пилота | 0.1.0, CustomModelProtocol / CPU ONNX FP32 | Исторический локальный пилот с реальным Box 5; закрытый SDK в этот репозиторий не включён |
| Публичный VLMP | **предложение 0.2.0-draft.1**, python-numpy-classification-v1 | Самостоятельный пример без приватных SDK; два локальных загрузчика, общая ONNX Runtime; совместимость этого профиля с Box 5 не проверена |
| VLSP | 0.1.0, python-scenario-json-v1 | Два самостоятельных host, Classification → JSON events/state; без VLBP |
| Защищённая выдача | 0.1.0 | Шифрование, подпись, offline entitlement и online grant в тестовом loopback сервисе; не sandbox и не промышленный сервер лицензий |

Публичный профиль VLMP явно выделен как новое предложение: он не меняет ранее испытанный пакет 0.1 и не наследует его заявление о Box 5. Профили не обещают произвольные модели, GPU, треки или все виды видеоаналитики. Проверенные результаты и команды — в [матрице совместимости](docs/ru/COMPATIBILITY.md).

## Начать за несколько минут

Требуется CPython 3.12 и публичные зависимости. Из корня репозитория:

```sh
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
export PYTHONDONTWRITEBYTECODE=1
export PYTHONPATH="model/src:scenario/src:security-runtime/src"
python model/src/public_model.py validate model/examples/channel-classifier
python model/src/public_model.py golden model/examples/channel-classifier
python model/tools/independent_host.py model/examples/channel-classifier
python tools/model_archive_roundtrip.py
python -m vl_scenario_package golden scenario/examples/target-scenario --policy development
python scenario/tools/independent_host.py scenario/reports/vlsp-target-scenario.zip
python -m pytest -q
python tools/check_links.py
```

Online-тесты открывают HTTP только на loopback; окружение должно разрешать локальные сокеты. В CLI `--policy development` нужен явно для открытого примера; эксплуатационный путь по умолчанию требует защищённую поставку. В публичных примерах нет постоянных ключей: тесты создают временные ключи и удаляют расшифрованные данные.
