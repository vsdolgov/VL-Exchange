# VL Exchange Security 0.1 — защищённая поставка

[English](SPECIFICATION.en.md) · Финальная редакция проекта · 03.11.2026

Открытый интерфейс не обязывает автора открывать свой код или веса. Эта финальная редакция проекта описывает шифрованную поставку VLMP/VLSP и право исполнения; публичная библиотека — испытательный прототип. Статус редакции не означает отраслевого утверждения или готовности к промышленной эксплуатации. Внутренний формат блоков VL не является частью межвендорного интерфейса.

## 1. Доверие и границы

Доверены издатель, системный администратор, часы, конфигурация доверия и принимающий host. Посторонний, получивший только поставку и лицензию без закрытого ключа установки, не должен получить plaintext. Противодействие администратору, извлекающему память, меняющему runtime или клонирующему секреты, не заявляется. TPM/HSM, attestation, обфускация и принудительная изоляция в библиотеке не реализованы. Отдельно поставленные веса не защищаются envelope сценария.

Корни доверия задаёт администратор до открытия пакета. Ключ издателя из самого пакета не является доверенным автоматически. Python выполняется с полномочиями процесса; ни шифрование, ни подпись не делают его безопасным. Требования к изоляции описаны в [модели угроз](THREAT-MODEL.ru.md).

## 2. Ключи и криптография

Издатель имеет Ed25519 signing key. Установка имеет X25519 key pair для расшифрования и отдельную Ed25519 pair для доказательства владения в online-режиме. Сервер online имеет отдельный Ed25519 signing key. Закрытые ключи не включаются в поставку. Публичные ключи издателя и сервера передаются по доверенному каналу.

Шифрование — libsodium sealed box над точными байтами ZIP, X25519/XSalsa20-Poly1305. Sealed box не удостоверяет отправителя; подлинность обеспечивает подпись лицензии с digest plaintext ZIP. Подписываются точные байты UTF-8 JSON, без повторной сериализации. JSON запрещает дубли ключей, NaN и Infinity. Base64 стандартный, с padding. SHA-256 представлен 64 строчными hex-символами. Сведения о примитивах: [libsodium](https://doc.libsodium.org/public-key_cryptography/sealed_boxes), [Ed25519 RFC 8032](https://www.rfc-editor.org/rfc/rfc8032.html).

## 3. Envelope

Директория содержит `envelope.json` и `package.sealed`. Обязательные поля envelope: `format="vl.exchange.protected"`, `version="0.1.0"`, `license` (Base64 точных байтов лицензии), `license_signature` (Base64 64 байтов подписи), `ciphertext_file="package.sealed"`, `ciphertext_sha256`. Иные поля 0.1.0 отклоняются. Приватный ключ нельзя указывать в manifest. Контроль ciphertext SHA-256 выявляет повреждение, но сам по себе не удостоверяет отправителя.

## 4. Лицензия

Подписываемое сообщение: ASCII `VL-EXCHANGE-LICENSE-V1`, нулевой байт, точные байты лицензии. Обязательные поля:

| Поля | Формат и требования |
|---|---|
| `format`, `version`, `audience` | `vl.exchange.license`, `0.1.0`, `vl.exchange.runtime` |
| `issuer_id`, `license_id`, `installation_id` | ASCII по `^[A-Za-z0-9][A-Za-z0-9._:-]{0,127}$`: 1–128 символов, первый — буква или цифра |
| `recipient_key_sha256` | SHA-256 32 raw bytes публичного X25519 key установки |
| `request_verify_key` | Base64 32 raw bytes публичного Ed25519 key установки |
| `package_sha256` | SHA-256 точных исходных байтов ZIP |
| `manifest_path`, `manifest_sha256`, `package_format` | Безопасный относительный путь manifest, его digest, объявленный `vl.*` format |
| `mode` | `offline` или `online` |
| `issued_at`, `not_before`, `expires_at` | Целые Unix UTC seconds от 0 до 253402300799 включительно, bool запрещён; `issued_at <= not_before < expires_at` |
| `permissions` | Ровно `["execute"]` |

Неизвестные поля отклоняются. Лицензия действительна при `issued_at <= now` и `not_before <= now < expires_at`. Перепаковка ZIP меняет идентичность поставки. Коммерческий договор определяет права использования и переноса; технический документ не предоставляет такие права. Квоты камер, биллинг и свободный перенос установки в v0.1 не реализованы.

## 5. Offline

Host проверяет подпись лицензии доверенным ключом издателя, формат, audience, режим, срок, право execute и привязку к ключу установки. Затем расшифровывает ZIP, проверяет package digest, manifest digest/format и соответствие содержимого спецификации. Импорт кода до этих проверок запрещён. Перед каждым вызовом и перед принятием результата проверяется срок.

Сеть и облако VL не нужны. Мгновенный удалённый отзыв offline невозможен без дополнительного канала: действуют срок и локальная политика администратора. Защита от отката часов не реализована независимо от доверенного администратора.

## 6. Online

URL, TLS trust store и ключ сервера задаются принимающей системой; URL из пакета не используется. До расшифрования нужен подписанный grant. HTTP разрешён только для явно включённого испытания loopback; рабочая интеграция требует HTTPS с проверкой сертификата и имени, без redirects.

Установка создаёт случайный nonce: 32 bytes, 64 lowercase hex. Подписываются ASCII `VL-EXCHANGE-REQUEST-V1`, нулевой байт и точные JSON bytes запроса. Поля: `format="vl.exchange.online-request"`, `version="0.1.0"`, `audience="vl.exchange.runtime"`, `license_sha256`, `license_id`, `installation_id`, `recipient_key_sha256`, `package_sha256`, `nonce`, `issued_at`. Транспортный JSON содержит `license`, `license_signature`, `request`, `request_signature`, всё в Base64.

Сервер проверяет лицензию издателя, срок, online-режим, execute, отзыв, подпись установки, соответствие идентичностей и digest, свежесть и отсутствие повторного nonce. Ответ содержит Base64 `grant` и `signature`. Подписываемый домен: ASCII `VL-EXCHANGE-GRANT-V1`, нулевой байт, bytes grant. Поля grant: `format="vl.exchange.online-grant"`, `version`, `audience`, `license_sha256`, `license_id`, `installation_id`, `recipient_key_sha256`, `package_sha256`, `nonce`, `issued_at`, `expires_at`, `permissions=["execute"]`. Максимальный TTL 300 seconds и не дольше лицензии. Эталонный сервер по умолчанию выдаёт grant на 60 seconds; настройка допускает 1–300. Допустимое расхождение `abs(server_now-request.issued_at)` по умолчанию 30 seconds, настраивается в пределах 0–120. Повтор nonce для того же license_id отклоняется; replay-cache содержит до 100000 записей и сохраняет запись на окно `2*max_clock_skew+1` seconds. Host проверяет `grant.issued_at <= now < grant.expires_at <= license.expires_at`.

Host проверяет подпись сервера, все привязки, nonce и срок. Ошибка сети, подписи или продления блокирует новые вызовы; автоматического перехода в offline нет. Отзыв применяется при следующей выдаче и не позже окончания действующего grant. В тестовом сервере replay cache хранится в памяти и сбрасывается при restart; устойчивое хранение и TLS termination не реализованы как production service.

## 7. Lease и результаты

`before_process()` обновляет grant при необходимости и возвращает immutable `ExecutionLease`. После вычисления host проверяет именно lease этого вызова до фиксации состояния, результата или события. Новый grant не легализует результат, вычисленный после истечения исходного lease. При ошибке обновления старое разрешение не используется для новых вызовов.

Guard не прерывает произвольный Python и не отменяет внешние действия уже работающего кода. Поэтому рекомендуемый worker не имеет прямого доступа к бизнес-системам: он возвращает кандидаты событий доверенному supervisor. Supervisor проверяет lease и формат результата, затем публикует событие. Полная процессная изоляция — задача платформы, не реализованная гарантия библиотеки.

## 8. Распаковка, лимиты и ошибки

Отклоняются traversal/absolute paths, дубли и symlink ZIP entries. Прототип ограничивает ZIP 128 MiB, распакованное содержимое 512 MiB, 1024 записи ZIP, включая каталоги, metadata 1 MiB; это лимиты реализации. Защищённый tmp-каталог удаляется при штатном выходе. После аварии и в памяти надёжное стирание не гарантировано; нужны приватный tmpfs и запрет доступа недоверенных пользователей к dumps и процессу.

Обязательные отрицательные случаи: неверные ключи/подпись, подмена лицензии/ZIP/manifest/ciphertext, неверные audience/mode/permissions, истечение до и во время вызова, неверные nonce/идентичности grant, replay, отказ и отзыв online. Результаты конкретного прогона публикуются отдельно от требований.

## 9. Перенос оплаченного решения

Формат обеспечивает техническую переносимость; договор должен сохранять право использования на новой совместимой платформе. В v0.1 установка связана с ключами: издатель перевыпускает envelope и лицензию для новой установки, сохраняя идентичность исходного ZIP. Старую online-лицензию отзывают; offline-перенос требует согласованной деактивации/срока и доверия администратору. Без канала связи нельзя доказать уничтожение всех прежних копий. Автоматический межвендорный лицензионный клиринг и общая служба платежей не реализованы.
