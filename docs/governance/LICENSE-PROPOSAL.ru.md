[Apache-2.0](https://www.apache.org/licenses/LICENSE-2.0) включает copyright grant, патентные условия и исключение товарных знаков. Его патентный grant ограничен claims участников, затрагиваемыми contribution; он не очищает права третьих лиц и сам по себе не является универсальным обещанием для любой реализации спецификации. [CC-BY-4.0 legal code](https://creativecommons.org/licenses/by/4.0/legalcode) исключает патенты и товарные знаки. [CC FAQ](https://creativecommons.org/faq/) рекомендует использовать специализированную software license для кода; поэтому для исполняемых примеров и схем предлагается software license, а не CC. Это предложение пока не принято.

Перед утверждением лицензий нужно зафиксировать юридического правообладателя, разрешение на служебные результаты и состав contributions, проверить происхождение каждого перенесённого файла. Не ставить автором правообладателя автоматически. Согласовать текст royalty-free/non-discriminatory обязательства по essential patent claims и процедуру раскрытия известных claims. Это отдельное решение: его нельзя подменять словами «открытый стандарт». Подтверждения отсутствия любых патентов нет.

Для вкладов предлагается DCO 1.1 и Signed-off-by после принятия лицензий; DCO подтверждает основание для вклада, а не передаёт исключительные права. Если нужен CLA, согласовать его отдельно; до этого не требовать передачу коммерческих решений. [DCO](https://developercertificate.org/).

## Переносимость коммерческого права

Главный тезис инициативы включает сохранение уже оплаченной аналитики. Для его исполнения договор издателя должен разрешать смену совместимой платформы без повторной покупки самой аналитики, с оговорёнными тарифами на адаптацию/поддержку, объёмом использования и порядком перевыпуска лицензии. Формат и тест совместимости не могут навязать это автору автоматически.

Предложение к типовым условиям: право исполнения принадлежит заказчику в согласованном объёме; смена совместимого host не прекращает его; старое право на установку заменяется новым; одновременное использование ограничено договором. Для offline заранее согласовать период миграции, деактивацию и доверенную процедуру, поскольку мгновенный отзыв недоступен. Эти положения пока не утверждённый договор и не реализованный сервис расчётов.

## Что согласовать

1. Юридический правообладатель и объём лицензируемых прав; состав файлов для этой публикации уже одобрен.
2. Apache-2.0 для кода/схем/нормативного текста и CC-BY-4.0 для prose.
3. Essential-patent политика, attribution и использование бренда.
4. DCO либо согласованный CLA.
5. Типовые права переноса коммерческой лицензии и процедура offline migration.

После решения добавить настоящие LICENSE/NOTICE, SPDX headers, manifest licenses, список third-party notices и дату одобрения. Пока лицензии имеют статус pending, опубликованные материалы нельзя описывать как реализацию с уже предоставленной открытой лицензией.
