# Развитие VL Exchange

[English](GOVERNANCE.en.md) · Предложение, Draft / Experimental

VL — инициатор. Проект не принят отраслью, рабочая группа пока не сформирована, внешних участников и их согласия не заявляем. Реализация не требует закрытого SDK, визуального редактора или облака VL. Коммерческий пакет может оставаться закрытым.

Каждый формат имеет отдельную версию и именованный профиль: версия формата, версия runtime и версия бизнес-решения — разные сущности. В 0.x изменения могут быть несовместимыми, но требуют нового version/profile ID и migration notes; опубликованная спецификация интерфейса не переписывается задним числом. Для 1.x предлагаем MAJOR при несовместимости, MINOR при совместимом расширении, PATCH для исправлений без изменения формата обмена. Строгий parser отклоняет неизвестные обязательные возможности; нельзя молча угадывать профиль.

Предложение изменения содержит проблему, use case, альтернативы, влияние на существующие пакеты, RU/EN текст, схемы, positive/negative vectors и migration plan. Автор не обязан отдавать свой коммерческий код или веса. Изменение обсуждается публично минимум 14 календарных дней; спорные несовместимые изменения — минимум 30. Сроки являются предложением, не существующим регламентом организации.

До появления рабочей группы maintainer VL фиксирует решение и основания публично. После присоединения двух независимых организаций предлагается технический совет: по одному представителю каждой организации, раскрытие конфликта интересов, кворум 2/3, согласие 2/3 присутствующих, без единоличного vendor veto. Состав, полномочия и патентные условия должны быть согласованы до применения этой процедуры.

Release candidate сопровождается immutable commit/tag, changelog, схемами и checksum demo. Публикация stable требует двух независимо разработанных host, тестирующих один неизменённый ZIP, описанных сред и публичного протокола. Общая runtime library/crypto dependency раскрывается. Два локальных host не называются двумя коммерческими платформами. Ни соответствие схемам, ни подпись издателя сами по себе не дают сертификата совместимости или безопасности.

На корпоративном сайте и техпортале указываются точные release/profile и ссылка на тот же tagged GitHub источник. Будущее заявление о совместимости должно относиться к конкретной версии решения, а не выводиться из наличия ONNX; незаполненные статусы экспорта в публичном каталоге не показываются. Архивные испытания и результаты текущего public profile разделены. Репозиторий проекта — [vsdolgov/VL-Exchange](https://github.com/vsdolgov/VL-Exchange). Контакт для уязвимостей ещё подлежит утверждению; не отправлять exploit или секрет в публичный issue.
