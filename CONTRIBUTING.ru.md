# Участие в VL Exchange

**Draft · [English](CONTRIBUTING.md)**

Начните с описания проблемы и минимального синтетического примера. Для нового интерфейса укажите версии/profiles, входы/выходы, состояние/время, семантику ошибок, угрозы и совместимость. Приложите RU/EN текст одинакового содержания, JSON Schema и golden tests. Несовместимое изменение оформляйте отдельно с планом перехода; не меняйте опубликованные bytes той же версии.

Запустите `python tools/verify.py` в окружении из README. Проверки требуют loopback для online-лицензий; сетевую ошибку не обозначайте PASS. Один и тот же пакет передайте двум самостоятельным host без изменения файлов и допусков, запишите версии и digests.

Не размещайте коммерческие веса, данные заказчиков, приватные SDK, лицензионные ключи или чужой код без права публикации. Публичный вклад не требует раскрывать собственную коммерческую разработку. Финальная outbound/inbound лицензия проекта ещё согласуется: до решения не представляйте черновые условия как предоставленные права.
