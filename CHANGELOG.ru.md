# Изменения

[English](CHANGELOG.md)

## 2026-11-03 — защищённая поставка моделей VLMP

Добавлены онлайн- и офлайн-защита модельных пакетов VLMP и проверка на двух host. Проверяются подпись, право на исполнение и срок действия разрешения после инференса; исходные ZIP не менялись. Защищённый сценарий с тремя защищёнными моделями также проверен через VideoPipe. [Профиль и результаты](drafts/v0.2/vlmp-unified/README.ru.md#защищённая-поставка-моделей).

## 2026-11-03 — эксперимент интеграции VLSP и объединённого VLMP

Добавлен синтетический сценарий VLSP с привязкой к пакетам детекции и классификации объединённого VLMP и сравнением эталонного исполнителя с независимой интеграцией VideoPipe при offline- и online-защите сценария. Прежний ZIP сценария не изменён. Подробнее — в [описании эксперимента и его ограничений](drafts/v0.2/vlsp-unified-integration/README.ru.md).

## 2026-11-03 — объединённый VLMP 0.2.0

Добавлены общий manifest VLMP 0.2.0 и два явных статических CPU ONNX-профиля — классификация и детекция; подготовлены два независимо реализованных host и воспроизводимые синтетические примеры. Каждый host также проверен на одном неизменённом ZIP каждой прежней опубликованной версии; исходные схемы, загрузчики и ZIP сохранены. Подробнее — в [спецификации, результатах и ограничениях совместимости](drafts/v0.2/vlmp-unified/README.ru.md).

## 2026-11-03 — финальные редакции проекта VL Exchange

Опубликованы финальные редакции спецификаций проекта; состав, сохранённые pre-release идентификаторы и ограничения проверок приведены в [описании выпуска](docs/governance/SPECIFICATION-RELEASE-2026-11-03.ru.md). Это не означает отраслевого признания, готовности к промышленной эксплуатации или предоставления дополнительных лицензионных прав. Байты существующих пакетов и wire-идентификаторы не изменены.

В reference security-runtime время лицензии и grant повторно проверяется после online-авторизации и непосредственно перед расшифрованием пакета. Регрессионные тесты охватывают смену секунды, истечение ответа, откат часов и совместимость прежних authorizer. Прямой вызов `OnlineAuthorizer.authorize` с прежним фиксированным `now` требует явного `clock` для проверки времени после ответа; `authorized_package` и `renew` передают часы автоматически.

## 2026-11-02 — проекты VLSP 0.2 и детекции

Добавлены экспериментальные спецификации VLSP 0.2: несколько моделей и трекеров, ошибки и жизненный цикл, необязательные профили входной очереди и асинхронных заданий МЛЛМ. Отдельно добавлен черновик детекции VLMP, синтетические примеры, выбранные reference-компоненты и тесты. Историческое сравнение с VideoPipe и очередью приведено с ограничениями; оно не подтверждает поддержку async в VideoPipe или промышленную производительность. У детекции и ранее предложенной классификации разные идентификаторы проектов и схемы. Подробнее — в [обзоре 0.2](drafts/v0.2/README.ru.md).

## 2026-11-01 — Draft / Experimental, кандидат публикации

Подготовлен самостоятельный двуязычный репозиторий. VLSP0.1 и общий профиль защиты перенесены без внутренних исходников платформы; public security API по умолчанию использует scenario manifest. Добавлен **предлагаемый** VLMP0.2.0-draft.1 / python-numpy-classification-v1 для воспроизведения без приватного SDK; он не заменяет VLMP0.1 и не проверен с Box5. Добавлены два независимых модельных host, два сценарных host, синтетические ZIP, conformance/security tests, сквозной actual inference→protected scenario и GitHub Actions. Состав материалов одобрен к публикации в vsdolgov/VL-Exchange; лицензии и патентная политика остаются на согласовании. README связывает репозиторий с опубликованными страницами инициативы, технического портала и статьи.

Отображаемое название компании — **VL**. Ссылки на домен компании удалены. Прежнее правило denylist зависимостей сохранено через точное сравнение digest корневого имени без его буквальной записи. Изменение бренда в docstring сценария меняет bytes пакета, поэтому синтетическое решение пересобрано как **1.0.1** с новой идентичностью manifest/ZIP; формат VLSP0.1, Python ABI и поведение не менялись. Актуальные отчёты получены повторным прогоном, прежние доказательства сохранены отдельно без переименования.
