# VLMP 0.2.0: единый формат для классификации и детекции

**Русский | [English](README.md)**

VL Model Package `0.2.0` объединяет общую структуру пакета и два профиля моделей: классификацию и детекцию. Пакет объявляет профиль явно; результаты классификатора и детектора остаются разными. Требования находятся в [спецификации](spec/SPECIFICATION.ru.md), машинная форма manifest — в [JSON Schema](spec/model-package.schema.json).

Оба профиля этого выпуска ограничены статическим ONNX, CPU, FP32 и batch 1. Модель задаёт размеры изображения; host приводит BGR к RGB и готовит тензор. Resize и crop выполняются до вызова и не являются неявной функцией профиля. GPU, другие движки, динамические размеры, сегментация и произвольные ONNX-модели не заявляются.

## Проверка на двух исполнителях

Синтетические [classification.zip](examples/classification.zip) и [detection.zip](examples/detection.zip) поочерёдно исполняются эталонным host и отдельно реализованным independent host. Каждый получает один и тот же неизменённый ZIP; вызовы ONNX Runtime выполняются на CPU, результаты сверяются с golden и между host. Сравнение также повторяет вызовы в обратном порядке и после других входов, проверяет отрицательные случаи и идентичность ZIP. Оба host используют общие JSON Schema, NumPy и ONNX Runtime. Они локальны; сторонний производитель и Box 5 не участвовали в испытании, а синтетические необученные модели не измеряют качество промышленной аналитики.

[Отчёт о проверке](reports/VERIFICATION.md) и [машинные результаты](reports/comparison.json) содержат хеши ZIP, ONNX-графов и исходников, результаты для каждого кадра и отрицательные проверки. [Тесты reference](reference/tests) и [independent](independent/tests) отдельно проверяют безопасность путей, целостность, графы и ошибки входа.

## Старые пакеты

В обоих host сохранены отдельные ветки для ранее опубликованных форматов — `0.2.0-draft.1` для классификации и `0.2.0-detection-draft.1` для детекции. На каждом host проверен один прежний ZIP каждого формата; полная совместимость со всеми допустимыми старыми пакетами не заявляется. Исходные ZIP, схемы и загрузчики не изменены. Новые host применяют дополнительные ограничения к ZIP-путям; independent host также ограничивает размер manifest и отклоняет внешние ONNX tensor data. Подробности — в [его описании](independent/README.md). Старая классификация содержит Python-код издателя и исполняется только в доверенном окружении; ни один из host не является песочницей. Исторический VLMP 0.1 / CustomModelProtocol с закрытым SDK этой проверкой не охвачен.

Миграция модели в новый manifest создаёт новый ZIP и новые хеши. Для защищённой поставки нужны новые подписи и права. Если VLSP-сценарий закреплён за digest старого model manifest, необходимо обновить его привязку и выпустить обновлённый сценарный пакет: его прежний ZIP не изменится автоматически. Запуск нового модельного пакета через существующие VLSP host и защищённую поставку в этих испытаниях отдельно не проверялся.

## Повторить проверку

Из корня репозитория на macOS или Linux с Python 3.12 и зависимостями корневого `requirements.txt`:

```sh
export PYTHONDONTWRITEBYTECODE=1
export PYTHONPATH="drafts/v0.2/vlmp-unified:model/src:scenario/src:security-runtime/src:drafts/v0.2/model/src"
python drafts/v0.2/vlmp-unified/tools/compare_hosts.py
python -m pytest -q --import-mode=importlib -p no:cacheprovider \
  drafts/v0.2/vlmp-unified/tests \
  drafts/v0.2/vlmp-unified/reference/tests \
  drafts/v0.2/vlmp-unified/independent/tests
```

`compare_hosts.py --output /tmp/vlmp-comparison.json` дополнительно сохраняет JSON. Демонстрационные ZIP можно побайтно пересобрать командой `python drafts/v0.2/vlmp-unified/tools/build_examples.py`; это не меняет ранее опубликованные пакеты. Тесты используют только локальные синтетические данные.
