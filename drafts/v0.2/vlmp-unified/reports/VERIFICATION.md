# VLMP 0.2.0 — проверка двух исполнителей

3 ноября 2026 года из локального checkout выполнен [сравнительный прогон](comparison.json). Reference и independently implemented host получили одни и те же ZIP; исходные байты, manifest и ONNX-графы зафиксированы хешами до и после. Оба host вызывали ONNX Runtime на CPU; в JSON приведён результат каждого вызова и сравнение с golden.

| Пакет | Версия | Разных входов | Вызовов на каждый host |
|---|---:|---:|---:|
| Новый классификатор | `0.2.0` | 4 | 11 |
| Новый детектор | `0.2.0` | 4 | 11 |
| Прежний классификатор | `0.2.0-draft.1` | 5 | 13 |
| Прежний детектор | `0.2.0-detection-draft.1` | 4 | 11 |

Для каждого набора выполняются прямой и обратный порядок, а также повтор исходного входа после другого. Все **46 golden-вызовов каждого host** совпали с заранее заданными результатами с указанными допусками и друг с другом. Дополнительно поданы по восемь воспроизводимых случайных изображений для каждого пакета: ещё 32 результата на host совпали между собой, но отдельного golden для этих входов нет. Число у reference host для legacy означает успешные вызовы исходного загрузчика; для новых профилей считаются непосредственные вызовы ONNX Runtime. Отдельный subprocess проверил отсутствие импортов reference runtime при инференсе каждого нового профиля независимым host.

Дополнительно прогон проверил отказ двух host при повреждённом digest, незаявленном файле, небезопасном пути, неподдерживаемой версии, неизвестном профиле или обязательной capability, несовпадении размеров, неправильной golden-категории и повторе manifest. Проверены неверные тип/форма кадра, изменение ZIP после загрузки и отсутствие влияния внешней мутации публичной копии manifest. Отдельные pytest-наборы проверяют повреждённые ONNX-графы, границы NPY и другие негативные случаи.

ZIP новых профилей: классификация SHA-256 `a7b6e4299faff1d98ec2c7b53892c7c3dfc6e4ecf1029078224bab65d8a4e95f`, детекция `39e2afcdbfd8ff9a29066cde92362b4cd9fde1fab851a0cec7d54f72e06341c9`. Прежние ZIP остаются побайтно прежними. Разные profile IDs и manifest не означают, что модель автоматически переносится в старый сценарий, закреплённый за другим digest.

Оба host локальные и используют общие JSON Schema, ONNX, ONNX Runtime и NumPy; проверка не является испытанием платформ двух производителей. Демонстрационные модели синтетические и необученные. Для старых форматов проверен один опубликованный ZIP каждого типа; дополнительные ограничения independent host перечислены в [его README](../independent/README.md). GPU, динамические модели, промышленная нагрузка, Box 5 и защищённая поставка новых моделей не проверены.
